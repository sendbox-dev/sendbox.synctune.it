Open-source sandboxing for coding agents

Give your coding agent a workspace, not your whole machine.

SendBox runs coding agents in dedicated Linux VMs on macOS and Linux. Keep your terminal workflow while explicitly choosing the files, network destinations, credentials and MCP tools a session can use.

SendBox Fleet adds shared governance for teams: signed policy profiles, credential grants and a central audit log.

Two projects, one boundary

Use SendBox on its own for a single developer or runner. Add SendBox Fleet when several people and hosts need to share policy, grants and audit evidence.

SendBox

An open-source Rust CLI for running coding agents in dedicated Linux VMs, through Apple Containerization on macOS and Kata Containers on Linux.

  • One reviewable YAML policy for commands, network destinations, credentials and MCP tools.
  • Workspace snapshots, diffs, failure rollback and tamper-evident lifecycle records.
  • Interactive terminal sessions, or headless runs with JSON events for scripts and CI.

SendBox Fleet

The shared governance service for SendBox governed sessions. Provider credentials never reach it; they stay in the SendBox host broker.

  • Operator-signed policy profiles shared across users and hosts, with project-scoped roles.
  • Session admission, credential grants, revocation and approved, expiring exceptions.
  • OpenID Connect sign-in and a hash-chained audit log with signed, anchored chain heads.

What a session gets, and what it doesn't

An agent needs to edit code, run commands and reach its model provider. It doesn't need everything else on your laptop or runner.

  • VM-backed isolation

    A dedicated guest kernel, not a workload sharing the host kernel.

  • Explicit workspace scope

    Share one project, or opt into a multi-repository workspace. Your home directory isn't mounted automatically.

  • Deny-first networking

    Allowed domains only. Direct external agent traffic and UDP/QUIC are blocked.

  • Scoped credentials

    Vault-backed secrets with separate GitHub, Copilot, MCP and registry paths, masked in output.

  • MCP tool policies

    Admit exact local or remote servers and allow or deny tools per server.

  • Package checks

    An optional npm proxy verifies and inspects packages before releasing their bytes.

  • Snapshots and audit

    Before and after snapshots, diffs and tamper-evident lifecycle records.

  • GitHub write controls

    Branch guards, or Safe Outputs for bounded writes without an agent write token.

An unavailable runtime or unsupported capability is an error, never a fallback to running on the host. Read the security model and the limitations for what isolation does and doesn't cover.

How they fit together

Both projects share the sendbox-governance contract. A host can govern sessions locally or through a shared Fleet service.

Standalone and local governance

Install the SendBox CLI and a runtime, generate .sendbox.yaml for a project and start sessions. Operators can require signed policy profiles and keep model provider keys on the host with governed sessions, using a grant authority that runs in process.

Shared governance with Fleet

Point the host's governance configuration at a Fleet service. Fleet authenticates people and CI, enforces project roles, admits sessions, issues and checks grants, and keeps the central audit log. Follow the deployment guide to run it with PostgreSQL and your identity provider.

Bring the agent you already use

Init profiles set the agent's entry command and initial inference hosts. They don't install the agent or log you in; your digest-pinned workload image provides the Linux agent and its tools.

Get started

SendBox supports macOS 26+ on Apple silicon and Linux on x86_64 or aarch64 with hardware or nested virtualization.

  1. Install SendBox and a runtime

    Install the CLI from the Homebrew tap, or download and verify a release. Then set up Apple Containerization on macOS or Kata Containers on Linux, and stage the signed guest bundle.

    $ brew install mbianchidev/tap/sendbox

  2. Configure your project and agent

    Generate a private .sendbox.yaml, store credentials outside shell history and validate the policy before starting a VM.

    $ sendbox init --project . --agent claude
$ sendbox secrets add ANTHROPIC_API_KEY
$ sendbox policy validate --config .sendbox.yaml

  3. Start a session

    Run the agent interactively with your workload image, or drop --interactive for headless automation. See the full quick start and the CLI reference.

Before installing a release, check the dependency security status and Homebrew update notes in the installation guide.
